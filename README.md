# Driver Diary

«Дневник смен водителя» — веб-приложение для учёта поездок водителей. Сервер написан на FastAPI с асинхронным JSON-хранилищем, клиент — на обычных HTML, CSS и JavaScript.

## Возможности

- регистрация и вход по номеру телефона;
- хранение паролей только в виде PBKDF2-хеша;
- HttpOnly cookie-сессия;
- отдельный журнал поездок для каждого водителя;
- добавление поездки с валидацией суммы, времени и способа оплаты;
- запрет дублей по `id` внутри журнала водителя;
- запрет пересекающихся поездок;
- поддержка поездок через полночь;
- дневная сводка: количество поездок, выручка, комиссия и сумма «на руки»;
- разбивка выручки по наличным и карте;
- серверная пагинация журнала;
- отдельное окно с деталями поездки;
- адаптивный веб-интерфейс для desktop и mobile.

## Запуск

Требуется Python 3.12 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Для локальной разработки можно задать секрет сессии:

```powershell
$env:DRIVER_DIARY_SESSION_SECRET = "local-development-secret"
```

Запуск сервера:

```powershell
python -m uvicorn app.main:app --reload
```

Адреса после запуска:

- веб-клиент: `http://127.0.0.1:8000/`;
- health-check: `http://127.0.0.1:8000/api/health`;
- Swagger UI: `http://127.0.0.1:8000/docs`.

При первом запуске нужно зарегистрировать аккаунт через веб-интерфейс. Журнал нового водителя пустой.

## API

Все endpoints поездок требуют авторизации. Сессия передаётся автоматически через cookie.

### Авторизация

- `POST /api/auth/register` — зарегистрировать пользователя.
- `POST /api/auth/login` — войти по телефону и паролю.
- `POST /api/auth/logout` — завершить текущую сессию.
- `GET /api/auth/me` — получить данные текущего пользователя.

Регистрация принимает:

```json
{
  "phone": "+7 (900) 123-45-67",
  "password": "strong-pass-1",
  "password_confirm": "strong-pass-1"
}
```

Номер нормализуется до цифр. Повторная регистрация телефона возвращает `409 Conflict`. Несовпадающие пароли возвращают `422 Unprocessable Entity`.

### Поездки

- `POST /api/trips` — создать поездку.
- `GET /api/trips?date=2026-10-01&page=1&page_size=10` — получить страницу поездок за день.

Пример поездки:

```json
{
  "id": "trip-001",
  "start": "2026-10-01T23:58:00+05:00",
  "end": "2026-10-02T00:22:00+05:00",
  "amount": 1500,
  "payment": "card",
  "commission": 150
}
```

Время должно быть timezone-aware. Новая поездка должна иметь `amount > 0`, `end` позже `start`, а `payment` должен быть `cash` или `card`.

Повторная отправка того же `id` не создаёт дубль. Ответ содержит `created: true` для новой поездки и `created: false` для уже существующей.

Если интервал пересекается с другой поездкой этого же водителя, API возвращает `409 Conflict`. Соседние интервалы разрешены: `13:00–13:30` и `13:30–14:00`.

Ответ списка содержит:

- `items` — поездки текущей страницы;
- `page` — номер текущей страницы;
- `page_size` — размер страницы;
- `total` — общее количество поездок за день;
- `total_pages` — общее количество страниц.

Параметр `page_size` ограничен диапазоном от `1` до `50`.

### Сводка

- `GET /api/summary?date=2026-10-01` — сводка текущего водителя за день.

Сводка содержит количество поездок, выручку, комиссию, сумму «на руки» и отдельные итоги для `cash` и `card`.

## Хранилище

- `data/trips.json` — поездки;
- `data/users.json` — пользователи и хеши паролей;
- `data/users.json` не добавляется в Git;
- тесты используют временные JSON-файлы и не меняют рабочие данные.

Путь к данным и изменяемые настройки вынесены в `app/config.py`. Для production необходимо задавать собственный `DRIVER_DIARY_SESSION_SECRET` и не хранить его в репозитории.

## Тесты

Запустить весь набор с подробным выводом:

```powershell
python -m pytest -v -ra --tb=short
```

Ожидаемый результат текущего набора:

```text
13 passed
```

Тихий режим:

```powershell
python -m pytest -q
```

Подробный режим с именами всех тестов:

```powershell
python -m pytest -vv
```

### Что тестируется

`tests/test_summary.py` проверяет фильтрацию по выбранной дате, выручку, комиссию, сумму «на руки» и разбивку наличных/карты.

`tests/test_storage.py` проверяет защиту от повторного `id` и миграцию старых поездок без `owner_id` первому владельцу.

`tests/test_overlap.py` проверяет запрет пересекающихся интервалов и разрешение последовательных поездок.

`tests/test_auth_api.py` проверяет регистрацию, нормализацию телефона, совпадение паролей, повторный телефон, вход, неверный пароль и logout.

`tests/test_api_access.py` проверяет, что журнал и сводка недоступны без авторизации.

`tests/test_trips_api.py` проверяет дубли через API, конфликт пересекающихся поездок, валидацию входных данных, пагинацию и изоляцию поездок между водителями.

`tests/conftest.py` создаёт отдельные временные JSON-хранилища для каждого теста.

В выводе может появляться предупреждение совместимости `TestClient/httpx`; оно не считается ошибкой, если тесты завершились строкой `passed`.
